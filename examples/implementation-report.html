01 · Outcome

What was delivered

Third-party authentication

Lakebed supplies verified Google identities. A single configurable email list grants owner access across devices.

Email access control

Every artifact starts with an empty recipient list. The server grants access only to the owner or explicitly added emails.

Sandboxed HTML

Interactive content runs without same-origin privileges, isolating it from the authenticated viewer.

Agent publishing

A zero-dependency script publishes through a secret-protected endpoint and returns the private link.

02 · Flow

How publishing works

  1. Generate

    Codex creates one self-contained HTML page.

  2. Publish

    The local script authenticates with a server-only token.

  3. Authorize

    The server stores an empty or explicit email allowlist.

  4. View

    A verified recipient signs in and opens the sandboxed page.

03 · Decision

Why Lakebed

Lakebed already provided deployment, identity, server execution, database transactions, secrets, and a stable subdomain. Because its object storage blocks HTML, the service stores pages in database chunks. The tradeoff is a compact personal service: 512 KiB per artifact within a 1 MiB state limit.
