01 · Capabilities

A compact publishing layer built for agent workflows.

The repository includes the service, browser interface, publishing API, setup automation, and a shared Codex and Claude Code skill.

01

Agent-native creation

Ask for a report or walkthrough. The skill creates one responsive HTML file, publishes it, and opens the result.

02

Private by default

New artifacts begin owner-only. Recipients are added deliberately after publishing.

03

Durable identity

Email invitations bind to immutable Lakebed user IDs after verified Google sign-in.

04

Stable updates

Reuse a slug to replace HTML at the same URL while omitted access settings stay intact.

05

Browser management

Owners upload, replace, download, delete, and manage visibility from the authenticated shell.

06

Self-hosted ownership

Your Lakebed deployment has its own state, owners, URL, and publishing token.

03 · Publish path

One prompt becomes one controlled URL.

Secrets stay in the local publisher and server environment. Artifact HTML is treated as untrusted content at the viewer boundary.

01 / BUILD

Agent creates HTML

A skill guides a responsive, self-contained page using verified project context.

02 / PUBLISH

Local script authenticates

A deployment-wide bearer token is sent only to the configured HTTPS origin.

03 / STORE

Server validates and chunks

Size limits are enforced before HTML is split into database-safe values.

04 / VIEW

Shell authorizes and isolates

The server checks access; the browser renders HTML without same-origin privileges.

04 · Boundaries

Small by design, explicit about trust.

These limits reserve room for metadata and access grants inside Lakebed’s capsule state budget.

512 KiBmaximum HTML per artifact
48 KiBmaximum stored chunk value
768 KiBworkspace HTML budget
1 MiBLakebed capsule state limit

Protected shell

The artifact iframe never receives allow-same-origin, so published HTML cannot become same-origin with the authenticated application.

Untrusted artifact

Scripts, forms, popups, and outbound requests can run inside the sandbox. Authors must keep secrets and sensitive source out of generated pages.

Bring your own Lakebed

Clone. Set one owner. Publish.

The setup command creates a random publishing token, deploys an owned service, verifies its health, and saves the resulting URL locally.

git clone https://github.com/none23/codex-artifacts.git
cd codex-artifacts
npm ci
npm run setup -- --owner you@example.com
